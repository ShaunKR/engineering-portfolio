# [doc] 개발 PL 협업·설계 가이드

PMP를 보유한 개발 PL로서 스쿼드 조직과 애자일 개발을 중심으로 일해 온 경험을 바탕으로, 개발 협업과 기술 의사결정 기준을 정리한다. MSA를 지향하되 서비스 분리는 업무 경계와 운영 여건을 함께 검토한다.

## 문서 성격

이 자료는 공개를 위해 새로 작성한 가이드와 템플릿이다. 과거 조직의 내부 규정이나 운영 기록 원본이 아니며, 아래 세부 규칙을 모두 실제 팀에 적용했다는 의미는 아니다. 규칙과 예시는 팀에서 검토할 제안 기준이다. 실제 적용 사례와 성과는 확인 가능한 자료가 생기면 별도로 연결한다.

## 적용 방법

1. 팀의 저장소, 배포 주기와 장애 위험을 확인한다.
2. 필요한 규칙부터 합의하고 담당자·예외 기준을 정한다.
3. 규칙을 PR 양식, 자동 검사, 작업 보드에 연결한다.
4. 리뷰 지연과 재작업 사례를 확인하고 회고에서 조정한다.

성과를 기록할 때는 적용 전후의 기간, 측정 방법과 표본을 함께 남긴다. 문서 작성만으로 생산성 향상이나 장애 감소를 주장하지 않는다.
