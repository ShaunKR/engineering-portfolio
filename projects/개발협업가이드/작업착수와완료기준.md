# [agile] 작업 착수·완료 기준

> 팀에서 검토할 제안 기준이다. 특정 팀의 실제 적용이나 성과를 주장하지 않는다.

## 착수 전 확인

작업의 목적, 인수 조건, 의존성과 불확실성을 확인한다. 다음 목록은 대화의 기준이며, 모든 작업에 같은 서류를 요구하는 승인 단계로 사용하지 않는다. 착수 기준은 Scrum의 필수 산출물로 규정된 것이 아니다.

- 해결하려는 사용자 또는 운영 문제가 설명되어 있는가?
- 관찰 가능한 인수 조건이 있는가?
- 필요한 데이터·접근 권한·타 팀 의존성이 확인됐는가?
- 불확실성이 크면 구현보다 조사나 실험을 먼저 할 필요가 있는가?

## 인수 조건과 완료 기준

인수 조건은 개별 기능의 기대 동작이고, 완료 기준은 여러 작업에 공통으로 적용할 품질 기준이다.

가상 예시: “브로커 중지 후 클라이언트가 재연결하고, 재연결 완료 후 발행한 시험 메시지를 수신한다”는 인수 조건으로 사용할 수 있다. 무손실을 요구한다면 발행·수신 식별자와 장애 구간을 포함한 별도 검증이 필요하다.

## 공통 완료 기준 제안

- [ ] 인수 조건을 검증하고 결과를 연결했다.
- [ ] 변경 위험에 맞는 테스트와 리뷰를 수행했다.
- [ ] 실패 처리와 설정 변경의 영향을 확인했다.
- [ ] 필요한 실행·운영 문서를 갱신했다.
- [ ] 배포 대상이면 복구 방법과 배포 후 확인 항목을 정했다.
- [ ] 미검증 항목과 알려진 제약을 숨기지 않았다.

공통 품질 기준을 충족하지 못한 작업을 완료로 계산하지 않는다. 범위를 나눌 수 있다면 독립적으로 확인 가능한 부분을 먼저 완료하고, 남은 항목은 별도 작업으로 추적한다. 완료와 운영 배포 여부는 구분한다.
