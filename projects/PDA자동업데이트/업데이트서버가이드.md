# Android APK 업데이트 서버 통합 `version.json` 가이드

## 1. 목적

이 문서는 다음 4개 시스템의 APK 수동 배포 업데이트를 위해 통합 `version.json` 규격과 안드로이드 앱 구현 예시를 정의한다.

대상 시스템:
- `flypick`
- `manualsorting`
- `followme`
- `suresorter`

운영 방식:
- 업데이트 서버는 IIS 웹서비스로 운영한다.
- 각 시스템 APK는 시스템별 폴더에 배치한다.
- 앱은 통합 `version.json`을 조회한 뒤 자기 시스템 버전을 확인한다.
- 서버 버전과 현재 앱 버전이 다르면 업데이트 안내 후 APK URL을 연다.

## 2. 서버 폴더 구조

업데이트 서버 기본 주소 예시:

```text
https://update.your-domain.com/
```

권장 폴더 구조:

```text
/flypick/
    flypick-1.0.0.apk
/manualsorting/
    manualsorting-1.0.0.apk
/followme/
    followme-1.0.0.apk
/suresorter/
    suresorter-1.0.0.apk
/version.json
```

실제 URL 예시:

```text
https://update.your-domain.com/version.json
https://update.your-domain.com/flypick/flypick-1.0.0.apk
https://update.your-domain.com/manualsorting/manualsorting-1.0.0.apk
https://update.your-domain.com/followme/followme-1.0.0.apk
https://update.your-domain.com/suresorter/suresorter-1.0.0.apk
```

## 3. 통합 `version.json` 규격

최소 속성만 사용하는 통합 구조이다.

```json
{
  "systems": {
    "flypick": {
      "version": "1.0.0",
      "url": "https://update.your-domain.com/flypick/flypick-1.0.0.apk"
    },
    "manualsorting": {
      "version": "1.0.0",
      "url": "https://update.your-domain.com/manualsorting/manualsorting-1.0.0.apk"
    },
    "followme": {
      "version": "1.2.0",
      "url": "https://update.your-domain.com/followme/followme-1.2.0.apk"
    },
    "suresorter": {
      "version": "2.0.1",
      "url": "https://update.your-domain.com/suresorter/suresorter-2.0.1.apk"
    }
  }
}
```

### 규칙

- `systems` 아래 key는 시스템명이다.
- `version`은 시멘틱 버전 문자열이다.
- `url`은 해당 시스템 APK 다운로드 주소이다.
- 앱은 자신의 시스템명을 알고 있어야 한다.
- 앱은 통합 `version.json`에서 자기 시스템 항목만 읽으면 된다.

---

## 4. 시멘틱 버전 규칙

버전 형식:

```text
MAJOR.MINOR.PATCH
```

예시:

```text
1.0.0  최초 릴리즈
1.1.0  기능 추가
1.1.1  버그 수정
2.0.0  큰 변경
```

주의:

이번 정책에서는 버전의 크고 작음을 비교하지 않는다.

현재 앱 버전과 서버 버전이 **다르면 바로 업데이트 대상**으로 판단한다.

예시:

```text
현재 버전: 1.2.0
서버 버전: 1.2.1
→ 업데이트

현재 버전: 1.2.0
서버 버전: 1.3.0
→ 업데이트

현재 버전: 1.2.0
서버 버전: 2.0.0
→ 업데이트

현재 버전: 1.2.0
서버 버전: 1.2.0
→ 최신
```

## 5. 협력사 구현 규칙

1. 앱 시작 시 `https://update.your-domain.com/version.json` 조회
2. 통합 JSON에서 자기 시스템명에 해당하는 항목 조회
3. 서버 버전과 현재 앱 버전 비교
4. 서버 버전과 현재 앱 버전이 다르면 업데이트 필요
5. 업데이트 버튼 클릭 시 `url`을 브라우저로 연다

## 6. 안드로이드 샘플 코드 (Kotlin)

### 6.1 시스템명 정의

```kotlin
object SystemName {
    const val FLYPICK = "flypick"
    const val MANUALSORTING = "manualsorting"
    const val FOLLOWME = "followme"
    const val SURESORTER = "suresorter"
}
```

### 6.2 버전 정보 모델

```kotlin
data class SystemVersionInfo(
    val version: String,
    val url: String
)
```

### 6.3 현재 앱 버전 읽기

```kotlin
import android.content.Context

object AppInfoUtil {
    fun getCurrentVersion(context: Context): String {
        val packageInfo = context.packageManager.getPackageInfo(context.packageName, 0)
        return packageInfo.versionName ?: "0.0.0"
    }
}
```

### 6.4 버전 일치 여부 비교 함수

```kotlin
object VersionComparator {

    fun isSameVersion(v1: String, v2: String): Boolean {
        return v1 == v2
    }
}
```

기준:
- `true` : 동일 버전
- `false` : 다른 버전

### 6.5 통합 `version.json` 읽기

```kotlin
import org.json.JSONObject
import java.io.BufferedReader
import java.io.InputStreamReader
import java.net.HttpURLConnection
import java.net.URL

object VersionApi {

    fun fetchSystemVersionInfo(versionJsonUrl: String, systemName: String): SystemVersionInfo {
        val url = URL(versionJsonUrl)
        val conn = (url.openConnection() as HttpURLConnection).apply {
            requestMethod = "GET"
            connectTimeout = 5000
            readTimeout = 5000
            setRequestProperty("Accept", "application/json")
        }

        try {
            val responseCode = conn.responseCode
            if (responseCode != HttpURLConnection.HTTP_OK) {
                throw RuntimeException("HTTP error: $responseCode")
            }

            val response = BufferedReader(InputStreamReader(conn.inputStream)).use { reader ->
                buildString {
                    var line: String?
                    while (reader.readLine().also { line = it } != null) {
                        append(line)
                    }
                }
            }

            val root = JSONObject(response)
            val systems = root.getJSONObject("systems")

            if (!systems.has(systemName)) {
                throw RuntimeException("System not found in version.json: $systemName")
            }

            val systemObj = systems.getJSONObject(systemName)
            return SystemVersionInfo(
                version = systemObj.getString("version"),
                url = systemObj.getString("url")
            )
        } finally {
            conn.disconnect()
        }
    }
}
```

### 6.6 업데이트 필요 여부 판단

```kotlin
object UpdateChecker {

    fun isUpdateRequired(currentVersion: String, serverVersion: String): Boolean {
        return currentVersion != serverVersion
    }
}
```

### 6.7 다운로드 URL 열기

```kotlin
import android.content.Context
import android.content.Intent
import android.net.Uri

object UpdateLauncher {
    fun openDownloadUrl(context: Context, url: String) {
        val intent = Intent(Intent.ACTION_VIEW, Uri.parse(url))
        context.startActivity(intent)
    }
}
```

### 6.8 전체 사용 예시

```kotlin
import android.os.Bundle
import android.widget.Toast
import androidx.appcompat.app.AlertDialog
import androidx.appcompat.app.AppCompatActivity
import kotlin.concurrent.thread

class MainActivity : AppCompatActivity() {

    private val versionJsonUrl = "https://update.your-domain.com/version.json"
    private val currentSystemName = SystemName.FOLLOWME

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        checkUpdate()
    }

    private fun checkUpdate() {
        thread {
            try {
                val serverInfo = VersionApi.fetchSystemVersionInfo(versionJsonUrl, currentSystemName)
                val currentVersion = AppInfoUtil.getCurrentVersion(this)

                val needUpdate = UpdateChecker.isUpdateRequired(
                    currentVersion = currentVersion,
                    serverVersion = serverInfo.version
                )

                runOnUiThread {
                    if (needUpdate) {
                        showUpdateDialog(serverInfo.version, serverInfo.url)
                    }
                }
            } catch (e: Exception) {
                runOnUiThread {
                    Toast.makeText(this, "업데이트 확인 실패: ${e.message}", Toast.LENGTH_SHORT).show()
                }
            }
        }
    }

    private fun showUpdateDialog(serverVersion: String, apkUrl: String) {
        AlertDialog.Builder(this)
            .setTitle("업데이트 안내")
            .setMessage("새 버전 $serverVersion 이 있습니다. 업데이트를 진행해 주세요.")
            .setPositiveButton("업데이트") { _, _ ->
                UpdateLauncher.openDownloadUrl(this, apkUrl)
            }
            .setNegativeButton("나중에", null)
            .show()
    }
}
```

## 8. 운영 절차

### APK 배포 절차

1. 새 APK를 해당 시스템 폴더에 업로드
2. 통합 `version.json`에서 해당 시스템의 `version` 수정
3. 통합 `version.json`에서 해당 시스템의 `url` 수정
4. 앱 실행 시 현재 버전과 서버 버전이 다르면 자동으로 업데이트 감지

예:

- 기존:

```json
"followme": {
  "version": "1.2.0",
  "url": "https://update.your-domain.com/followme/followme-1.2.0.apk"
}
```

- 변경 후:

```json
"followme": {
  "version": "1.3.0",
  "url": "https://update.your-domain.com/followme/followme-1.3.0.apk"
}
```

## 9. 협력사 전달용 핵심 요약

### 서버

- 통합 `version.json` 파일 1개 사용
- APK는 시스템별 폴더에 저장
- 각 시스템은 `systems.{systemName}` 항목 사용

### 앱

- 앱은 자기 시스템명을 고정값으로 보유
- 앱 실행 시 통합 `version.json` 조회
- 자기 시스템 버전만 조회
- 서버 버전과 현재 앱 버전 문자열이 다르면 업데이트 여부 판단
- 필요 시 APK URL 오픈
