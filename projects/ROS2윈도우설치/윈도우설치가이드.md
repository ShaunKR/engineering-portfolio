# ROS 2 Humble Windows 개발 환경 설치

과거 Windows 11 설치 메모를 정리한 가이드다. 버전과 절차는 당시 기록을 기준으로 하며 현재 배포 환경에서 재검증하지 않았다. 설치 전 대상 배포판의 공식 문서와 설치 파일 제공 여부를 확인한다.

## 1. 언어 환경과 관리자 셸

원본 메모에는 한글 환경에서 오류가 발생해 영문 언어팩을 기본으로 사용했다는 관찰이 있다. 오류 원인이 규명된 것은 아니므로 영문 환경을 ROS 2의 필수 조건으로 단정하지 않는다.

Chocolatey 설치는 [공식 설치 안내](https://chocolatey.org/install)를 확인한다. 원문의 관리자 PowerShell 설치 명령은 [작업 기록](설치작업기록.md)에 남겨 두었다. 이 문서의 명령을 작성 과정에서 실행하지 않았다.

## 2. Python과 런타임

관리자 명령 프롬프트에서 당시 사용한 버전을 설치한다. 원본에는 Python 설치 후 재부팅이 필요하다고 기록돼 있다.

```bat
choco install -y python --version 3.8.3
choco install -y vcredist2013 vcredist140
choco install -y openssl --version 1.1.1.2100
setx /m OPENSSL_CONF "C:\Program Files\OpenSSL-Win64\bin\openssl.cfg"
```

`setx /m`은 시스템 환경변수 설정이다. 원문의 “사용자 변수” 설명과 구분하고, 실제 설치 경로에 해당 파일이 있는지 확인한다. 변경 후 새 셸에서 환경변수를 확인한다.

## 3. Visual Studio, OpenCV와 CMake

- Visual Studio 2019 설치. 원문에는 C++ CMake 도구 선택을 해제했다고 기록돼 있다.
- VS2019용 OpenCV 3.4.6의 `opencv` 폴더를 `C:\opencv`에 배치한다.
- CMake 3.16.9 설치 후 실행 파일 경로를 PATH에 추가한다.

```bat
setx /m OpenCV_DIR C:\opencv
```

PATH에서 확인할 항목:

```text
C:\opencv\x64\vc16\bin
C:\Program Files\CMake\bin
```

원문에 OpenCV PATH 등록 여부가 확인되지 않은 장비가 언급돼 있다. 이를 생략 가능한 설정으로 해석하지 않는다. 로컬 설치 파일은 이 저장소에 포함하지 않는다.

## 4. 네이티브·Python 의존성

원문은 별도 `package` 폴더를 `C:\package`에 복사해 로컬 Chocolatey 소스로 사용한다. 해당 패키지 묶음은 공개 자료에 포함되어 있지 않다.

```bat
cd /d C:\
choco install -y -s package asio cunit eigen tinyxml-usestl tinyxml2 bullet
python -m pip install -U pip setuptools==59.6.0
python -m pip install -U catkin_pkg cryptography empy importlib-metadata lark==1.1.1 lxml matplotlib netifaces numpy opencv-python PyQt5 pillow psutil pycairo pydot pyparsing==2.4.7 pyyaml rosdistro
```

일부 의존성은 버전이 고정되어 있지 않다. 현재 실행하면 당시와 다른 조합이 설치될 수 있다. 원문의 “오류 시 재실행”은 원인 분석을 대신하는 해결책으로 보장하지 않는다. 실패한 패키지와 메시지를 따로 확인한다.

## 5. Qt와 기타 도구

Qt 5.12.12 설치 시 `MSVC 2017 64-bit` 구성 요소를 선택한 기록이다. 로그인은 본인 계정으로 진행한다. 실제 설치 경로를 확인한 후 다음 변수를 설정한다.

```bat
setx /m Qt5_DIR C:\Qt\Qt5.12.12\5.12.12\msvc2017_64
setx /m QT_QPA_PLATFORM_PLUGIN_PATH C:\Qt\Qt5.12.12\5.12.12\msvc2017_64\plugins\platforms
choco install -y cppcheck curl git winflexbison3
python -m pip install -U colcon-common-extensions coverage flake8 flake8-blind-except flake8-builtins flake8-class-newline flake8-comprehensions flake8-deprecated flake8-docstrings flake8-import-order flake8-quotes mock mypy==0.931 pep8 pydocstyle pytest pytest-mock vcstool
```

원문은 RQt용 Graphviz 설치 파일과 `xmllint` 폴더를 추가로 사용한다. Graphviz를 설치하고 `C:\xmllint\bin`을 PATH에 추가하는 절차를 기록했으나 해당 설치 파일은 제공하지 않는다.

## 6. 긴 경로와 ROS 2 소스 빌드

원문에 기록된 관리자 PowerShell 설정:

```powershell
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" `
  -Name "LongPathsEnabled" -Value 1 -PropertyType DWORD -Force
```

[Microsoft 긴 경로 안내](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation)를 참고한다. 레지스트리 값만으로 모든 도구의 긴 경로 동작이 보장된다고 판단하지 않는다.

원문에는 `dev\humble`과 `dev\ros2_humble`, C·D 드라이브 경로가 혼재한다. 아래 명령은 설명을 위해 `C:\dev\ros2_humble`로 통일한 예시다. 실제 경로에 맞춰 조정한다.

Visual Studio 2019의 x64 Native Tools Command Prompt에서:

```bat
mkdir C:\dev\ros2_humble\src
cd /d C:\dev\ros2_humble
vcs import --input https://raw.githubusercontent.com/ros2/ros2/humble/ros2.repos src
colcon build --merge-install
```

## 7. empy 호환성 오류 대응 기록

원문에 남아 있는 오류:

```text
AttributeError processing template 'msg.idl.em'
AttributeError: module 'em' has no attribute 'BUFFERED_OPT'
```

대응 방법으로 기록된 명령:

```bat
python -m pip install empy==3.3.4
```

설치에 사용한 Python과 빌드가 사용하는 Python이 같은지 확인하고 빌드를 다시 진행한다. 원본에는 조치 후 전체 성공 로그가 없으므로 모든 환경에서 해결됐다고 단정하지 않는다.

## 8. ros2_dotnet 연동 절차

먼저 ROS 2 설치 경로가 준비돼 있어야 한다. 아래는 원문을 바탕으로 경로를 통일한 워크스페이스 구성 예시다.

```bat
call C:\dev\ros2_humble\install\local_setup.bat
mkdir C:\dev\ros2_dotnet_ws\src
cd /d C:\dev\ros2_dotnet_ws
curl -fSL https://raw.githubusercontent.com/ros2-dotnet/ros2_dotnet/main/ros2_dotnet_humble.repos -o ros2_dotnet_humble.repos
vcs import src < ros2_dotnet_humble.repos
git clone --branch humble https://github.com/ros2/rosidl src\ros2\rosidl
colcon build --merge-install
```

원문의 다운로드 명령에서 인증서 검증을 생략하는 `-k` 옵션은 정리본에서 제외했다. 파일을 별도로 준비한 경우 대상 폴더에 배치하고 다운로드 단계를 생략할 수 있다.

원문에는 `rosidl` 추가 clone이 기록돼 있으나 현재 가져온 소스 목록에 이미 같은 경로가 있는지 확인해야 한다. 필요 여부는 기반 ROS 설치 방식과 ros2_dotnet의 지침을 검토한다. .NET SDK 버전과 연동 성공 로그는 원문에 명시되어 있지 않다.
