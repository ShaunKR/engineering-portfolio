# [delivery] 릴리스 운영 가이드

> 팀에서 검토할 제안 기준이다. 실제 운영 배포 이력이나 승인 체계가 아니다.

## 준비

- 대상 커밋·태그와 배포 산출물을 식별한다.
- 변경 범위, 설정·스키마 변경과 의존 서비스 호환성을 확인한다.
- 배포 담당, 진행·중단 판단자와 장애 연락 경로를 정한다.
- 사전 검증 결과와 배포 후 확인할 지표를 연결한다.
- 롤백 또는 전진 수정 가능 여부를 검토한다.

담당자는 책임 범위를 뜻하며, 모든 릴리스에 별도 승인자를 추가하라는 의미는 아니다. 승인 수준은 변경 위험과 조직 기준에 맞춘다.

## 릴리스 기록 양식

```markdown
# 릴리스 식별자

- 대상 커밋 또는 태그:
- 대상 환경과 배포 범위:
- 담당자 및 진행·중단 판단 책임:
- 배포 예정 구간:

## 사전 검증과 알려진 제약

## 적용 순서와 의존성

## 중단 조건
- 지표와 임계 조건:
- 관찰 기간:

## 복구 방법과 데이터 제약

## 배포 후 확인 결과

## 후속 작업
```

## 복구 판단

코드 버전을 되돌릴 수 있어도 데이터와 외부 시스템 변경은 되돌리지 못할 수 있다. 스키마 변경은 이전 코드와의 호환 기간과 제거 시점을 함께 검토한다. 복구 절차가 확인되지 않았으면 확인되지 않았다고 기록한다.

구체적인 오류율·지연 임계값과 관찰 시간은 서비스의 정상 범위와 위험을 기준으로 정한다. 예시 숫자를 검증 없이 운영 기준으로 사용하지 않는다.

## 배포 후

주요 사용자 흐름, 오류, 지연과 적체를 확인하고 담당자를 정해 관찰한다. 이상이 있으면 중단 조건에 따라 판단하고 실제 조치와 결과를 남긴다. 성공 기록에도 미확인 영역과 후속 작업을 함께 적는다.
