## 협업·설계 자료

- [doc] [개발 PL 협업·설계 가이드](development-playbook/README.md): 공개용으로 재작성한 제안 기준과 템플릿. 과거 적용 실적이나 운영 결과를 뜻하지 않습니다.

## 이름 표기

작업 제목 앞에 `[network]`, `[messaging]`처럼 분야를 표시합니다. 기술 정리 문서는 `[doc]`으로 표시합니다. 폴더명은 짧은 영문 소문자와 하이픈을 사용합니다.

## 작업 추가 방법

`projects/작업명/` 아래에 코드와 설정, 설명을 함께 둡니다. 별도 재현 환경이 있으면 `lab/`으로 분리합니다. 공통으로 사용하는 이미지만 저장소의 `assets/`에 둡니다.

작업별 README에는 다음 내용을 작성합니다.

1. 작업 목적과 해결하려던 문제
2. 사용 기술과 실행 환경
3. 구현 내용과 구성도
4. 실행 및 확인 방법
5. 실제 결과와 근거 링크
6. 미검증 항목과 남은 제약

필요할 때 `results.md`와 로그를 추가합니다. 결과가 없는 작업은 구현 또는 설정 수준에서 확인한 범위를 명시합니다. 과거 경험을 적는 경우 현재 남아 있는 자료와 기억에 의존한 내용을 구분합니다.
